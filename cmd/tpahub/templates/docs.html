HOW IT WORKS

From .deb to apt install.

TPA Hub keeps the service layer small. TPA generates and signs the repository; TPA Hub stores, publishes, and serves it.

1. Install

curl -fsSL https://tpa.lupricht.net/install.sh | sudo bash

2. Register and log in

tpahub register --server https://tpa.lupricht.net
tpahub login

3. Create and publish

tpahub repo create tools
tpahub publish tools ./my-package_1.0.0_amd64.deb
tpahub status JOB_ID

4. Configure another machine

tpahub repo add REPOSITORY_ID --token READER_TOKEN
apt update
apt install my-package

Private repositories use a repository reader token. Public repositories can be added without one. APT continues to verify the repository signature with its signed-by keyring.

Plan overview

Same capability. Different capacity. Plan differentiation is resource-based, not feature-based. Nano, Standard and Pro provide the same core TPA Hub capabilities.

Nano · AVAILABLE NOW: 5 MB storage and 1 GB monthly repository egress.

Standard · COMING SOON: 500 MB storage and 20 GB monthly repository egress for normal hosted package repositories.

Pro · COMING SOON: pay as you go, with storage and egress growing independently in 500 MB storage blocks and 20 GB egress blocks. The intended differences are resource capacity and, for Pro, the billing model—not access to core features.

Current storage usage is measured as the exact sum of the currently published canonical .deb payload sizes across your repositories. Repository metadata, temporary uploads, workspaces, caches and historical uploads are excluded. Measurement can decrease when packages are removed. Nano storage capacity is enforced before a publish commits canonical artifacts; egress enforcement and billing are not implemented.

Uploads are included subject to technical rate and request limits. These are intended resource numbers, not package-count limits. See the Nano efficiency explanation for illustrative capacity estimates.

Future billing model

Pro is planned around gradual, predictable usage. Storage is measured using ceil(storage usage / 500 MB) and is intended to use the billing period's highest block, rather than repeated upload/delete recalculations. Egress is measured using ceil(monthly egress / 20 GB). Storage and egress grow independently.

Before an intentional upload crosses a storage block, a future interface should show the current and new billed capacity and ask for confirmation. Egress cannot usually pause external downloads, so future notifications are intended around 50%, 80%, and 95% of the current block. These confirmations and notifications are not implemented yet.

The intended experience is small increases in usage leading to small increases in cost—not a dramatic jump at a threshold. Future optional spend controls may include maximum storage blocks, egress blocks, or monthly PAYG spend. No billing provider, charging, or usage accounting is implemented today.

Using Mema with TPA Hub

If your software already has a reliable upstream, you can package a Mema recipe instead of mirroring the complete application. TPA Hub distributes the small recipe package; Mema retrieves the actual software at installation time. See the Neovim example and Nano explanation.
