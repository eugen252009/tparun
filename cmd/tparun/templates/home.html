Give your Debian packages a clear path to users.

How it works

One package workflow, from build to installation.

01 · Build

Create a .deb

Use your existing Debian packaging or build tooling.

02 · Publish

Choose a repository

Publish packages to a repository you own and manage.

03 · Inspect

Check provenance

04 · Install

Use standard APT

After you deliberately trust the source, install and update packages with APT.

Why TPA.run

A repository is more useful than a download link.

Predictable delivery

Repository metadata gives Debian systems a repeatable way to discover versions, resolve packages, and update them.

Visible trust

Signed metadata and repository-specific credentials make the source and its trust decision explicit.

Small is supported

Nano is designed for a handful of packages, internal tools, utilities, and lightweight applications.

Public or private

Public packages can be consumed without an account. Publishing and private repository management require an account.

Install safely

Review the source before you configure APT.

The signed deb822 source file is published for inspection, with an embedded signing key. The repository it references is not active yet, so do not add it to APT or use it as an installation command.
