TPA.run

CLI-first package distribution for Debian systems.

TPA.run is a CLI-first platform for building, managing, and distributing APT packages across Debian-based systems.

Nur APT

# install
sudo tparun add tpa.run/r/you/my-repo
sudo apt update
sudo apt install my-app
Get Started

Build, publish, install

One package path, three steps.

Use TPA or your existing build tooling to create a .deb, publish it to a TPA.run repository, and install it on your systems through standard APT tooling.

# build
tpa build ./my-app

# publish
tparun stage ./my-app_1.0.0_amd64.deb
tparun publish tpa.run/r/you/my-repo

# install
sudo tparun add tpa.run/r/you/my-repo
sudo apt update
sudo apt install my-app

A TPA.run account is required to publish packages. Public repositories can be used without registration, while private repositories use repository-scoped credentials.

Why packages

Small repositories can still be serious infrastructure.

You do not need a huge software catalog to benefit from package-based distribution.

A small repository can give internal tools, personal infrastructure, utilities, and custom applications a repeatable installation and update path through standard APT tooling.

For workflows that need more than installing a single package, tools such as Mema can use the same package infrastructure to provision runtimes and development tooling in a reproducible way.

Nano is designed for exactly these smaller repositories: a handful of packages, proper repository metadata, signed distribution, and a standard APT workflow without maintaining a large software catalog.

Repository trust

Install TPA.run.

Download the repository bootstrap package and let APT handle the rest.

curl -fL https://tpa.run/tparun-bootstrap.deb \
  -o tparun-bootstrap.deb
sudo apt install ./tparun-bootstrap.deb
sudo apt update
sudo apt install tparun

Discover public tools

Useful tools built on the same package workflow.

Public repositories can be discovered and used without registering.

Mema

Mema provisions developer runtimes and tools through packages instead of one-off installation scripts. It helps make development environments repeatable while keeping the underlying package workflow visible.

mema list

Bloom

Bloom provides reusable capabilities and tooling that can be discovered and composed for more specialized workflows. It builds on the same infrastructure but is not required to use TPA.run.

bloom search "package discovery"
