Reference and concepts

Understand the package path.

TPA.run connects Debian packages, signed repositories, and the standard APT workflow. Use this page to understand the contracts; use the How-to guide for task-oriented steps.

Install the CLI

curl -fsSL https://tpa.run/tparun.sources -o /tmp/tparun.sources
echo 'd705adf0cc1943be3c46e11bab749710caaaf29e1d88fe956cdcd848cbfb073d  /tmp/tparun.sources' | sha256sum -c -
sed -n '1,12p' /tmp/tparun.sources

Repository trust

Adding an APT repository is a trust decision: packages from that source may later be installed and executed with the normal privileges of the package manager. Inspect the source first and add only repositories you deliberately trust.

TPA.run signs repository metadata and uses repository-specific keyrings. The current TPA.run signing fingerprint is:

EDCEE63AA803737C8ABBC1E4A34190A2829D5E54

Keep signature verification enabled. Reader credentials authorize downloads from one repository; treat them as secrets.

Inspect repositories

Inspection does not configure APT. Use show to review a repository's identity, owner, visibility, and package information before deciding whether to add it.

tparun show https://tpa.run/r/eugen/dev-tools

On a machine that already has managed sources, list them without changing anything:

tparun installed
tparun installed --verbose

Only after reviewing the repository URL, publisher, signing information, and package list should you use add. The add command writes system APT configuration and normally requires root.

Consume public packages

Public repository metadata and packages can be consumed without a TPA.run account. First inspect the repository; then configure it and install the package you intend to use. TPA.run's own CLI installation is pending; these commands assume a qualified CLI is already available.

tparun show https://tpa.run/r/eugen/mema
sudo tparun add https://tpa.run/r/eugen/mema
sudo apt update
sudo apt install mema

Use the repository's own package names and instructions. TPA.run does not automatically execute repository configuration or package installation.

Publish packages

Publishing requires an account with an active entitlement. Create a repository, stage package bytes locally, inspect the publication plan, and publish deliberately.

tparun login https://tpa.run
tparun create my-repo
tparun stage ./my-package_1.0.0_amd64.deb
tparun status
tparun publish https://tpa.run/r/you/my-repo

The CLI validates authentication, authorization, package identity, and capacity before publication. A repository is private by default; change visibility only when you intend to publish it.

tparun edit https://tpa.run/r/you/my-repo visibility

For multiple packages, stage the complete set and inspect tparun status before publishing. Failed or cancelled publication preserves local staging for retry.

Private repositories

Private repositories require a repository-scoped reader credential for package consumption. Reader credentials do not grant publishing, administration, or ownership.

tparun show https://tpa.run/r/you/private-tools
sudo tparun add https://tpa.run/r/you/private-tools

The CLI prompts for the repository password without echoing it. APT credentials are written to a restricted file; do not put them in shared shell history.

Usage and limits

Published storage

Storage is the sum of canonical published .deb payloads across an account's repositories. Metadata, temporary workspaces, and historical uploads are excluded from that measurement.

Repository egress

Delivered package and repository metadata body bytes count, including partial range responses. Website pages, uploads, API calls, HEAD, and 304 responses do not count.

Billing status

Usage previews are not invoices. Stripe Sandbox checkout, where enabled, is test-only. Standard, Pro, and live usage-based charging are not currently available.
